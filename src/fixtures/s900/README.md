# S-900 MediaSource fixture

`assets` contains five dedicated 640×360, 15fps VP8 WebM segments generated by FFmpeg. A gold ball rolls down an unnumbered apparatus with a turning wheel and into an open gift. Each two-second reel continues the position and wheel phase of its predecessor; no text or ordinal is painted into the footage. `lead.webm` is always prepended; `a.webm` through `d.webm` have anonymous independently shuffled symbols and shuffled preview-card positions in the game. Wrong orders still produce and play the selected native MSE stream. The stage appends each already encoded reel once at an explicit `timestampOffset`; it does not repeat a borrowed frame or encode at runtime.

The stage's point is the real `MediaSource` append order, not a transcoder. Regenerate these Git-managed assets only with:

```powershell
$env:BUSYCUBE_FFMPEG_PATH = "<trusted-ffmpeg-path>"
$env:BUSYCUBE_FFPROBE_PATH = "<trusted-ffprobe-path>"
node scripts/generate-busycube-s900-s910-fixtures.mjs --s900-only
```

`assets/media-source-segments.json` contains only the segment timing and MIME data required at runtime. The generator validates FFmpeg probe metadata while updating the assets; normal CI does not revalidate committed WebM bytes.

FFmpeg's WebM muxer randomizes `TrackUID` even with bitexact flags. The generator normalizes the standard track UID and its tag target to a fixed value after encoding; it does not alter encoded frames. Running the same generator twice with the same toolchain therefore produces byte-identical Git assets without maintaining a separate checksum file.
