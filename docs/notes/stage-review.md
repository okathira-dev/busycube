# 全ステージ・人手確認台帳

レビュー開始時点の89ステージ・204箱について、画面レビュー、ブラウザ権限、実機センサー、PWA、OAuth、外部機器、環境差の確認結果を一件ずつ記録する作業台帳の入口。
解法仕様の正本は各 `src/stages/S-xxx/stage.tsx` の日本語JSDocであり、以下の文書は確認項目、実施環境、結果、証跡を管理する。
既存の確認結果と再確認対象を保持する。未確認の解消や、今後の見直しが不要かを判断するまでは台帳を残す。

2026-10-28: 改修前の件数・表示型番・人手チェックは履歴として保持する。改修後の現行構成は[ステージ索引](../specifications/stage-catalog.md)、製品実装・自動検証と人手未確認の別管理は[実装作業表](./stage-review-implementation.md)を参照する。

## 台帳

- [実環境・公開判定](./stage-review-environments.md): ブラウザ、OS、端末、PWA、権限、外部機器の確認ケースと公開可否
- [ステージレビュー共通手順](./stage-review-guide.md): チェックの意味と全ステージ共通の横断レビュー
- [Dステージ](./stage-review-d.md): レビュー開始時のD 38件と追加・改修後の確認項目
- [Pステージ](./stage-review-p.md): レビュー開始時のP 26件と追加・改修後の確認項目
- [Lステージ](./stage-review-l.md): レビュー開始時のL 25件と追加・改修後の確認項目

## 実装状態と見直し用の記録

- [全ステージ・パズル設計AIレビュー](./stage-review-puzzle-ai.md): 改修前の89ステージ・204箱への初回提案。後の合意・現行実装とは区別して保持する。
- [対話で確認した方針](./stage-review-decisions.md): 個別相談の合意・暫定案・未決事項を記録。方針確認済みと実装の対応済みを区別する。
- [事前PoC結果](./stage-review-poc-results.md): 実測範囲・未観測と成立条件。製品の実装完了・実機合格とは別の記録。
- [実装作業表・検証記録](./stage-review-implementation.md): D→P→Lの製品実装、統合・分離の依存関係、自動検証と人手確認の別管理。

## 進め方

1. 共通手順と実環境・公開判定の条件を確認する。
2. 実装作業表で改修後の状態を確認し、D、P、Lの既存記録と照合する。表示番号・箱IDが変わった場合は現行索引とJSDocで確認対象を決め、古いチェックを新条件へ自動転記しない。
3. 実機や権限が必要な結果は、個別チェックだけで完了にせず実環境・公開判定台帳へ証跡を残す。
4. 用意できない環境は未検証のまま明示し、推測で合格にしない。
