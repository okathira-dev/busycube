- 改修・削除が終わり、必要な検証結果が揃ったものだけを「対応済み」へ移す。

## 共通方針

- 各ステージの相談では、プレイヤーの実操作、実APIと成功条件、現在の画面、指摘、改善案を毎回説明する。
- 解法の文章は原則置かず、アイコン・数字・配置・操作への反応で伝える。数字だけの手掛かりもよく、全てをアイコンにする必要はない。
- 箱ラベルはアイコン名を基本とし、同じアイコンが複数あるだけでは区別情報を追加しない。特徴的な位置以外に、色・ID・解法を足さない。
- 触れない対象は試して分かるようにし、言葉で先に説明しない。フォーカス表示は明確にする。権限・安全・拒否・未対応・解除等の必要情報とは区別する。
- タイミングゲームや実機入力の各部位を試す問題も採用できる。API機能を無判断で順に実行するだけの構成は見直す。
- Web API一覧由来とBlackbox模倣由来の重複を後で横断整理する。API名より、プレイヤーの操作と発見の重複を見る。ただし、重複だけで削除を決めず個別合意を優先する。

### D-019 / S-360 — 窓を渡る音

- 方針確認済み・未実装。現在のWebRTC接続・切断の二箱を、実際に鳴らしたシグナル符号をマイクで認識する二箱へ変更する。

- 符号の仕様、送受信UI、認識精度、同一端末での音の回り込み、識別子の長さ・reset時の扱いは実装前に検討する。
