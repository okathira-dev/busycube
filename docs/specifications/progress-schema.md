# ローカル状態と進捗バックアップ

## データの責務

主保存先は IndexedDB の `busycube-player-v2`、`state/current`。公開前のため旧DB・旧バックアップからの移行は行わず、旧データも自動削除しない。

ローカル状態は次を持つ。

| 項目 | 意味 |
| --- | --- |
| `schemaVersion: 1` | ローカル保存形式 |
| `storageId` | 保存領域の識別。進捗リセットでは変更しない |
| `revision` | ローカル更新の順序。端末間では比較しない |
| `settings.locale` | 同じ保存領域で共有する言語設定 |
| `epoch` | 進捗の世代。リセットで変更する |
| `stages` | ステージ別の `solvedBoxIds` と任意の `markers` |

総問題数・達成数はmanifestから導出する。クリア日時、観測ログ、生入力、永続訪問ログは保存しない。入場中の開封演出も永続進捗から分離する。

## 更新と複数タブ

更新は達成追加・マーカー追加・進捗統合・言語変更・リセットの操作に限定する。任意文書の置き換えAPIは公開しない。

最新状態の読込、操作の適用、保存を一つのreadwrite transactionで行う。初回作成もこの境界に含め、同時起動したタブは同じ識別情報を共有する。設定操作は設定だけを変更し、達成とマーカーは和集合で統合する。

状態管理は保存済み状態と未保存操作を分離する。保存待ちに追加された操作は、先行する保存の完了で消さない。別タブの通知とfocus・pageshow・visibility復帰で再取得し、古いrevisionの応答は適用しない。通知の成否は保存の安全性に影響させない。

保存不能時は未保存操作をメモリに保持する。再試行は接続の再取得と最新状態への操作適用を行う。ページを閉じた後の未保存操作の保持は保証しない。初期読込が成功するまではステージを開始せず、既存データを空として上書きしない。不正な保存内容は通常操作で上書きしない。

## リセット

進捗と世代を一括更新し、設定と保存領域IDを保つ。世代の異なる達成・マーカー・統合は拒否する。別タブは世代変更時に古い未保存進捗を破棄し、実行中ステージを再作成する。失敗したリセットを通常の保存再試行で自動実行しない。

音響の同一保存領域判定には保存領域ID、迷路や通知金庫の問題生成には進捗世代を使う。温室・バックグラウンド取得・オフラインコンテンツの保存済み結果も世代で区別する。

## バックアップ形式 version 2

Driveの保存名は `busycube-progress-v2-` を接頭辞とし、旧形式の開発用バックアップを検索対象に含めない。

JSONとDriveは `schemaVersion: 2`、`sourceStorageId`、`stages` のみを持つ。言語・ローカル更新番号・進捗世代・一時試行は含めない。取り込み元の保存領域IDは現在の保存領域IDへ適用しない。

箱とマーカーは追加として統合し、現在manifestに存在しない過去のIDも保持する。未知の箱を現行の達成数へ数えず、異なる条件の達成へ転記しない。不正形式と将来versionは拒否する。

Drive同期結果は開始時の世代へだけ統合する。通信中に進んだローカル進捗と設定を失わない。リセットはローカル操作であり、Driveの削除とは別。リセット後に改めて同期や取込みを実行すればバックアップの達成が復元される。

## 検証

更新・再試行・リセット競合は状態管理の単体テストで検証する。IndexedDBの実接続と同じ保存領域の複数ページは `e2e/progress-storage.spec.ts` で検証する。実機権限や外部機器の確認をこれらの自動テストで代替しない。
