# ステージ仕様・実装ガイド

ステージを実装する前に、このテンプレートを複製して仕様を埋める。コードから明らかな処理ではなく、ギミックの意図、環境差、権限、後片付け、進捗互換性を記録する。

## 識別

- ステージID:
- 表示ラベル（日英、後で推敲可）:
- 実装ディレクトリ: `src/stages/S-xxx/`
- manifest: `src/stages/S-xxx/manifest.ts`（ID、表示名、play条件、ローカル箱ID、lazy loadだけを置く）
- stage module: `src/stages/S-xxx/stage.tsx`（箱の見た目、配置、解法を置く）
- stage-localization: `src/stages/S-xxx/locale.ts`（UIに表示する日本語・英語を置く）
- 対応ギミックID:
- 問題箱ID:
- 大区分:
- 内部タグ:
- 状態: 調査待ち / 試作待ち / 評価待ち / 採用 / 保留 / 却下

### ステージ実装JSDoc

ステージコンポーネントの直前へ、プレイヤーが最初に読む開発者向け解法説明を日本語で置く。短い英語の要約だけ、API名の列挙だけ、実装処理の逐語的な説明だけでは不十分である。各箱を独立した箇条書きにし、実操作、観測する値・event、厳密な成功条件を、JSDocだけで解ける粒度で書く。権限・保存・送信・対応環境もステージ固有の事実だけを記す。

全ステージに共通するnegative case、cleanup、人手確認、UI・アクセシビリティ観点は[全ステージ・人手確認台帳](../notes/stage-review.md)へ一度だけ定義し、各ステージの確認欄へ寄せる。非自明なcleanup順序や競合対策は、必要な実装箇所のコメントまたはテストで保証する。

```ts
/**
 * S-xxx
 *
 * 目的: プレイヤーが何を発見するステージか。
 * 最初の一手: 画面を見て最初に行う操作。
 * 箱ごとの解法:
 * - B01「箱名」: 実操作、観測する値・event、厳密な成功条件。
 * - B02「箱名」: 実操作、観測する値・event、厳密な成功条件。
 * 使用API: 使用するWeb APIとbrowser機能。
 * 権限・privacy: 権限要求の契機、保存・同期・送信しないデータ。
 * 対応環境: 必須browser、OS、機器、非対応時の扱い。
 */
```

表示ラベル、button、status、aria-label、エラーなどのUI文言はstage-localizationへ置き、JSDocへ重複させない。ステージ名と箱名は各 `S-xxx/locale.ts` の `stageName` / `Bxx` semantic keyへ置く。`locale.ts`自体の役割を説明する定型コメントは置かず、翻訳上の非自明な制約がある場合だけ理由をコメントする。`manifest.ts` はローカル箱IDだけを公開し、アイコン・色・ヒント・構造は `stage.tsx` のstage moduleへ置く。ファイル名、export名、テスト名、URL、保存キーへ表示文言を転記しない。
